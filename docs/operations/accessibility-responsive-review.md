# Accessibility and responsive review

## Review scope

Review authentication, dashboard, planning/timeline, budget/payment terms, guests, checklist, vendors, rundown, custom fields, and attachments at approximately 400px and desktop widths.

## Checklist

- [ ] Keyboard focus is visible and logical.
- [ ] Inputs, selects, links, and icon-only controls have accessible labels.
- [ ] Loading, validation, error, success, and empty states are available.
- [ ] Destructive actions require confirmation.
- [ ] Status is communicated with text and not color alone.
- [ ] Dense tables contain horizontal overflow rather than page overflow.
- [ ] Primary touch targets remain usable on narrow screens.
- [ ] Export, download, and print controls remain discoverable for authorized users.

Record each defect with route, viewport, severity, reproduction, fix, and verification evidence. A mobile primary-flow failure, inaccessible authorization boundary, or financial ambiguity is release-blocking.
