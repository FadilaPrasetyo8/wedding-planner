# M3 Finance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. This session must execute inline; the user prohibited agents and task tools.

**Goal:** Deliver complete wedding-scoped budget scenarios, budget/payment management, savings tracking, finance summaries, audit evidence, and Inertia UI without entering M4+.

**Architecture:** Add finance as wedding-scoped vertical slices inside the existing Laravel/Inertia modular monolith. Database constraints and Policies enforce isolation; transactional Actions own multi-record mutations and audit records; support classes calculate authoritative aggregates; React renders explicit server props and submits Inertia forms.

**Tech Stack:** Laravel 13, PHP 8.3, PostgreSQL, Inertia 3, React 19, TypeScript, Tailwind CSS 4, PHPUnit, focused Vitest/React Testing Library.

**Spec:** `docs/superpowers/specs/2026-09-10-m3-finance.md`

## Global Constraints

- Preserve all completed M0–M2 behavior and existing uncommitted work.
- Do not implement vendors, attachments/payment proofs, custom fields, exports, or any M4+ feature.
- Use PostgreSQL `BIGINT` whole-rupiah values; never floats or formatted money in persistence.
- Every finance row has direct `wedding_id`; tenant-sensitive references use composite same-wedding foreign keys.
- Owner/editor may mutate; viewer is read-only; non-members receive 403 and cross-wedding nested resources 404.
- Use focused tests after each slice. Run `composer run ci:check`, `npm test`, `npm run build`, and fresh PostgreSQL migration/seeding only once at M3 completion.
